<h1> Up server with express and connect to MongoDB with mongoose </h1>

1. Створюємо папку для проекту
2. Cтворюємо `index.ts`
3. Ініціалізуємо проект `npm init`, далі натискаємо ентер Enter -> створюється `package.json`
4. Інсталюємо необхідні пакети в проект за допомогою - [ `npm install` або `yarn add` або `pnpm install`]:

🚀

- `express` [ це мінімалістичний і гнучкий фреймворк для Node.js, який використовується для створення веб-серверів та API ]
- `nodemon` [ це утиліта для Node.js, яка автоматично перезапускає ваш сервер або додаток щоразу, коли ви вносите зміни у вихідний код ]
- `jsonwebtoken` [ це бібліотека для роботи з JSON Web Tokens (JWT) в Node.js. Вона дозволяє створювати, підписувати та перевіряти токени, що широко використовується для аутентифікації та авторизації користувачів у веб-додатках ]
- `mongoose` [ це бібліотека для Node.js, яка слугує об’єктно-документальним маппером (ODM) для роботи з базою даних MongoDB. Вона дозволяє розробникам працювати з MongoDB, використовуючи схеми та моделі, що спрощує маніпуляцію даними і додає рівень абстракції для перевірки даних, валідації та роботи з middleware ]

  `Основні можливості Mongoose:`
  - Схеми (Schemas):
      Дозволяють визначити структуру документів, типи даних, обов’язкові поля та інші властивості.

  - Моделі (Models):
      Створені на основі схем, моделі дозволяють виконувати операції CRUD (створення, читання, оновлення, видалення) над документами.

  - Валідація:
      Вбудовані засоби перевірки даних під час збереження в базі.

  - Middleware (Проміжне програмне забезпечення):
      Дозволяють виконувати певні дії перед або після виконання операцій (наприклад, збереження документа).

  - Методи та статичні методи:
      Можна додавати власні методи до моделей для розширення функціоналу.

- `bcrypt` [ для хешування паролів з метою підвищення їхньої безпеки. Вона застосовується в бекенд-розробці для захисту паролів користувачів перед збереженням у базі даних ]
- `express-validator` [ це набір middleware для Express.js, який забезпечує зручну валідацію та санітизацію даних, що надходять у HTTP-запитах. Він допомагає перевіряти коректність введених даних, робити їх безпечними для подальшої обробки та запобігати потенційним атакам через невірно відформатовані або шкідливі дані ]

  `Основні можливості express-validator:`
  - Валідація:
    Легко перевіряти поля запиту за допомогою різних правил, наприклад, чи є поле email валідною електронною адресою, чи містить пароль достатню кількість символів тощо.

  - Санітизація:
    Забезпечує очищення даних, видалення непотрібних символів, приведення до потрібного формату тощо.

  - Гнучкість:
    Можна створювати кастомні валідатори та правила перевірки.

  - Інтеграція з Express:
    Використовується як middleware, що дозволяє легко інтегрувати валідацію у маршрути Express.

1. Завантажує `Insomnia` -> для тестування API [ дозволяє розробникам легко створювати, відправляти та аналізувати HTTP/HTTPS запити. Він є популярною альтернативою іншим інструментам, таким як Postman ]
2. Реєструємося на MongoDB `https://cloud.mongodb.com` - створюємо `Cluster` [db] і здійснюємо `connect` -> де ми копіюємо ссилку на нашу створену db і за допомогою `mongoose` підключаємося до db, використовуючи при цьому логін та пароль адміна
3. Створюємо папку `models` -> де будуть всі наші `schemas` [ створюються за допомогою `mongoose` ] для створення сутностей в бд
4. Створюємо папку `validations` -> де за допомогою пакета `express-validator` валідуємо дані перед відправкою на збереження в db
5. Встановлюємо `MongoDB Compass` - це офіційний графічний інтерфейс для роботи з MongoDB, який дозволяє візуалізувати, досліджувати та керувати базами даних без необхідності використання командного рядка. Він розроблений для спрощення процесу розробки, адмінстрування та аналізу даних у MongoDB.
6. Створюємо папку `utils` - для загальних функцій [ checkAuth ]
7. Створюємо папку `controllers` - для винесення логіки з index.ts
8. Пишемо функціонал на завантаження файлів -> для цього встановлюємо бібліотеку `multer`. В `index.js` створюємо `storage` для завантажених файлів
9. Пишемо міделвеа для обробки помилок валідації `express-validator` в папці `utils`
10. Налаштовуємо `Open API` в файлі `swagger.ts`
